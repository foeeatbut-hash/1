# Данные проекта: план вместо записи

Flux ведёт проектную документацию инженерного отдела. Тихо испорченные данные
здесь дороже отказа: неверную цифру в ведомости замечают через недели, когда по
ней уже заказали оборудование. Отсюда правила, которые не обсуждаются.

## 1. Разбор никогда не пишет в базу

Любой путь «внешние данные → проект» делится надвое:

```
источник → ИЗВЛЕЧЕНИЕ → РАСПОЗНАВАНИЕ → НОРМАЛИЗАЦИЯ → СОПОСТАВЛЕНИЕ
        → ПЛАН (что произойдёт) → ПРЕДПРОСМОТР → ЗАПИСЬ одной транзакцией
```

Парсер выдаёт разобранное с оценками уверенности. Запись — отдельный шаг после
подтверждения человеком.

Готовое, что надо переиспользовать, а не писать заново:

| Нужно | Где лежит |
|---|---|
| План импорта оборудования | `server/equipmentPlan.ts` — `planEquipmentImport`, `RangeRule`, `applyEdits`, `filterBySelection` |
| Предпросмотр дерева с диффом | `src/components/EquipmentImportPreview.tsx` |
| План захвата и классы конфликтов | `src/capture/plan.ts` |
| Числа, единицы, ключи | `server/normalize.ts` — `parseRuNumber`, `canonicalUnit`, `normalizeKey` |

## 2. Фрагмент не удаляет

Если источник — часть документа (выделение с экрана, одна строка бланка), из
отсутствия чего-то в источнике **не следует**, что этого нет в проекте. План по
фрагменту не содержит удалений вообще. Иначе одна выделенная строка сносит
установку.

Полный документ — другое дело: там секция «пропало из бланка» уместна, но
показывается отдельно и требует подтверждения.

## 3. Ручные правки уважаем

У элементов есть `overrides` — значения, поправленные инженером вручную. Импорт,
молча кладущий поверх них новые данные, — дефект. Такое изменение показывается
красным и решается поштучно: «моё» или «из бланка».

## 4. Единицы молча не пересчитываем

кПа → Па, мм.вод.ст. → Па — только подсказка в предпросмотре. Тихое изменение
инженерных чисел недопустимо, даже когда пересчёт очевидно верен.

## 5. Сопоставление не угадывает по мелочи

Нормализация кодов обязана сохранять строение:

- разделитель между буквой и цифрой — оформление: `AHU-2` = `AHU 2` = `AHU2`;
- разделитель **между цифрами** значим: `бл2.1` ≠ `бл21` — это разные блоки;
- омоглифы приводим: русская `А` = латинская `A` (см. `normCode` в
  `src/capture/recognize.ts`).

Похожесть по написанию предлагаем **только при совпадении цифр**. `AHU-21` и
`AHU-211` — разные аппараты; предложить связать их значит потерять позицию.

## 6. Откат обязателен

Любая массовая запись сопровождается возможностью отмены. Снимок прежних
значений снимается **до** записи — после неё восстанавливать нечего. Образец:
`capture-apply` / `capture-undo` в `server.ts` и отчёт в
`src/components/CaptureReview.tsx`.

## 7. Личность — из сессии, а не из запроса

Обработчик не имеет права верить полю `userId`, `senderId`, `actorId`,
пришедшему от клиента: их подставляет кто угодно, а идентификаторы коллег видны
в списке сотрудников. Кто обращается — только `(req as any).authUser.id`.

На этом уже обожглись в мессенджере: чужую переписку можно было вычитать
запросом, написать от чужого имени, отредактировать и удалить чужое сообщение.
Проверка прав была, но сравнивала присланный идентификатор с присланным.

Право на чтение переписки — участие в ней (`isChatParticipant`, `isGroupMember`);
право на правку — авторство. Проверяется в `scripts/test-chat-privacy.ts`.

## 8. Программа офлайн, «ИИ» — программный

Требование заказчика, не пожелание: программа работает на сервере компании,
а весь «интеллект» в ней **программный** — алгоритмы, словари, локальная база
знаний. Никаких обращений к чужому API, ни во время работы, ни «опционально,
если есть ключ».

В Flux сейчас нет ни одного такого обращения. Помощник (`src/assistant/`) —
локальный разбор запроса по базе знаний. Предлагать языковую модель для разбора
бланков, поиска, подсказок или распределения данных нельзя по трём причинам
сразу: отдел работает в сети без интернета, данные проектов наружу не уходят, и
инженер должен иметь возможность проверить любое решение программы глазами.

Что делать вместо этого, когда задача выглядит «под ИИ»: словарь и правила
(`src/capture/vocab.ts`), сравнение по строению кода (`normCode`), расстояние
Дамерау—Левенштейна, обучение на прошлых решениях пользователя
(`src/import/learn.ts`), оценки уверенности и предпросмотр. Это проверяемо и
воспроизводимо, в отличие от ответа модели.

Правило проверяется механически: `scripts/test-architecture.ts` ищет в коде
адреса известных сервисов языковых моделей и роняет проверку, если найдёт.

# Проверка работы

## Наборы проверок

Логика, у которой есть правильный ответ, проверяется скриптом. Запуск:

```bash
npx tsx scripts/test-<имя>.ts
```

Что уже есть: `test-capture` (распознавание захвата и конфликты),
`test-constructor-fn` (своды по проекту), `test-architecture` (границы между
слоями и размер файлов, см. skill `flux-architecture`), `test-blank-parser`,
`test-normalize`, `test-doc-import`, `test-nlp`, `test-assistant`,
`test-api` (требует поднятого сервера, см. ниже).

Формат — простой и одинаковый, без фреймворка: счётчик, функция сравнения,
названия проверок по-русски и по существу.

```ts
const eq = (name: string, got: any, want: any) => { /* … */ };
eq('разделитель между цифрами значим', normCode('бл2.1') === normCode('бл21'), false);
console.log(`\n${ok} проверок пройдено, ${fail} провалено`);
process.exit(fail ? 1 : 0);
```

Название проверки должно говорить, **что именно** сломается: «разные номера не
считаются похожими» лучше, чем «тест 4».

Проверки пишутся до того, как объявить готовым. На этом проекте они уже
несколько раз ловили дефекты, которые выглядели правильно в коде: слипание
`бл2.1` с `бл21`, привязку `AHU-21` к `AHU-211`, потерю кодов с цифры.

## Типы и сборка

```bash
npx tsc --noEmit    # ноль ошибок; любая новая — своя, чинить
npx vite build
npm run build:electron
```

## Интерфейс

Для нового экрана — снимок и просмотр, а не «выглядит правильно». Схема:
поднять `vite preview`, открыть страницу в Chromium через `playwright-core`,
снять снимок, посмотреть.

```js
const b = await chromium.launch({
  executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome',
  args: ['--no-sandbox'],
});
```

Проверять обе темы (`colorScheme: 'light' | 'dark'`), горизонтальную прокрутку
(`document.documentElement.scrollWidth - clientWidth` должно быть 0) и ошибки в
консоли (`pageerror`, `console` типа `error`).

Если верстка ведёт себя странно — **измерять**, а не гадать: `getBoundingClientRect`,
`getComputedStyle`. Так нашлось, что кнопка с классом `.ok` обнуляла ширину
бейджам `.badge.ok` — столкновение имён в каскаде, на глаз неотличимое от
случайности.

## Сервер здесь поднимается — этим надо пользоваться

Раньше здесь было записано, что сервер в контейнере не запускается. Это
неверно: `npx tsx server.ts` поднимает Express на порту 3000, создаёт SQLite в
`database/`, синхронизирует схему и засевает администратора `RaupovKhKh` с
паролем `1122`. Через полминуты по API можно работать по-настоящему.

```bash
nohup npx tsx server.ts > /tmp/srv.log 2>&1 &
until curl -s localhost:3000/api/health >/dev/null; do sleep 3; done
npx tsx scripts/test-api.ts
```

`scripts/test-api.ts` — дымовая проверка HTTP-слоя: вход, отказ по чужому и
подделанному токену, основные списки, запись и удаление. Гонять её обязательно
до и после переноса маршрутов из `server.ts` в `server/routes/*` — перенос
легко сделать «почти правильно».

Осторожно с `pkill -f "tsx server.ts"`: строка совпадает с собственной командной
строкой оболочки, и она убьёт сама себя. Писать `pkill -f "tsx serv[e]r.ts"`.

Остаётся непроверяемым: мессенджер между двумя живыми пользователями, захват с
экрана целиком (нужен Electron и буфер обмена), сборка exe.

Для такого честная формулировка: «проверено разбором кода, типами и сборкой; на
живых данных не наблюдал». Не выдавать рассуждение за наблюдение — если в
отчёте сказано «работает», это должно означать, что я это видел.

# Захват с экрана: свёрнутый пульт → разбор → теги и данные

Проектирование (без внедрения). Задача: инженер держит перед собой чужой бланк,
письмо, PDF или таблицу поставщика — и переносит оттуда данные в программу
выделением, а не перепечатыванием. Программа при этом свёрнута в угол экрана и
не мешает.

Документ опирается на разбор кода: `electron/main.ts` (окна, `desktop:capture`,
пример `window:open-sticker`), `electron/preload.ts`, `src/import/*`
(извлекатели, OCR, `recognize.ts`, `valueGrammar.ts`, `dictionary.ts`),
`server/equipmentPlan.ts`, `server/normalize.ts`, `src/components/TagImportWizard.tsx`,
`src/components/EquipmentImportPreview.tsx`, `src/screens/Registry.tsx`,
`src/screens/Equipment.tsx`. Продолжает `docs/blank-import-design.md`.

---

## 1. Главный принцип: это не новый импорт, а новый источник

В программе уже есть конвейер, выстроенный в разборе импорта бланков:

```
источник → ИЗВЛЕЧЕНИЕ → РАСПОЗНАВАНИЕ → НОРМАЛИЗАЦИЯ → СОПОСТАВЛЕНИЕ → ПЛАН → ПРЕДПРОСМОТР → ЗАПИСЬ
```

Захват с экрана встаёт **первым звеном и только им**. Всё, что дальше, уже
написано и проверено: `planEquipmentImport` считает план, `EquipmentImportPreview`
его показывает, `normalize.ts` приводит числа и единицы, `TagImportWizard`
умеет сопоставлять колонки и ловить дубли.

Из этого следуют три правила, которые дальше не обсуждаются:

1. **Захват никогда не пишет в БД напрямую.** Он доводит текст до промежуточной
   модели и отдаёт в тот же план. Никакого второго пути записи.
2. **План захвата не содержит удалений.** Захват — это фрагмент, а не документ.
   Из того, что в выделении чего-то нет, не следует, что этого нет в проекте.
   Секция «пропало из бланка» для захвата не строится вообще — иначе выделение
   одной строки снесёт установку.
3. **Один экран с шагами**, без вложенных подтверждений — правило одного диалога,
   как в Конструкторе и мастере импорта.

## 2. Как устроен сам захват — честно

Здесь главная развилка, и врать себе про неё нельзя: **прочитать выделение в
чужом окне напрямую нельзя**. В Windows нет способа, доступного Electron, взять
выделенный текст из постороннего приложения. Есть три обходных пути, и они
разного качества.

| Путь | Что даёт | Чем платим |
|---|---|---|
| **А. Буфер обмена** — инженер выделил и нажал Ctrl+C, мы читаем буфер | работает в любом приложении; из Excel и Word приходит **структура** (см. §2.2) | нужен Ctrl+C, то есть лишнее нажатие |
| **Б. Синтетический Ctrl+C** — мы сами посылаем копирование в активное окно по нажатию галочки | ровно тот сценарий, что описан: «выделил → нажал галочку» | нужен ввод в чужое окно: либо нативный модуль (`nut.js`), который придётся пересобирать под каждую версию Electron и тащить в портативный exe, либо PowerShell `SendKeys` (лишние 100–300 мс и запрет политиками); плюс затирается буфер инженера |
| **В. Снимок области + OCR** | берёт то, что вообще не выделяется: сканы, картинки, чужие вьюеры | распознавание с ошибками, нужен предпросмотр каждой цифры |

**Решение.** Основа — путь А, потому что он единственный точный и без зависимостей.
Но пульт не ждёт галочку молча: пока режим захвата включён, он **следит за
буфером** и, как только там появляется новое содержимое, показывает «захвачено:
10 строк» и зажигает галочку. Для инженера это выглядит так, как он и описал:
выделил, копирнул, нажал галочку — программа развернулась. Путь Б добавляется
позже как настройка «копировать самому» и снимает Ctrl+C для тех, у кого он
заработал; путь В — второй инструмент пульта (§3.1), нужный для бланков-сканов,
которых у поставщиков большинство.

### 2.1. Ловушка, которую нельзя пропустить

Если галочка просто читает буфер, то нажатие при **пустом выделении** затащит в
программу то, что инженер копировал час назад — чужой пароль, кусок переписки, —
и он этого не заметит. Поэтому:

- при входе в режим захвата снимается отпечаток буфера (хеш + метка времени);
- галочка активна **только если буфер изменился после этого момента**;
- иначе на пульте висит «выделение не изменилось — выделите текст и скопируйте»,
  и галочка серая.

### 2.2. Буфер — это не только текст

`clipboard.availableFormats()` для копии из Excel/Word отдаёт несколько
представлений, и богатейшее из них надо брать первым:

| Флейвор | Что в нём | Куда ведёт |
|---|---|---|
| `text/html` | настоящая таблица `<table>` с ячейками и объединениями | прямо в сетку промежуточной модели — колонки известны, ничего угадывать не надо |
| `text/plain` с табуляциями | TSV: строки и колонки | та же сетка, объединения потеряны |
| `text/plain` без табуляций | сплошной текст | режим «список» (§5.1) или разбор строк «ключ-значение» (§8.2) |
| `text/rtf` | текст с оформлением | резерв: жирность как признак заголовка группы (то, чего SheetJS CE не даёт, см. фазу 1 разбора бланков) |
| `image/*` | картинка | сразу в OCR (§3.1), минуя текстовый разбор |

Это важнее, чем кажется: копия из бланка Excel приносит **готовую таблицу**, а
значит классификатор колонок из `recognize.ts` (§3.1 разбора бланков) работает
на захвате без единой доработки.

### 2.3. Окно пульта

Отдельный `BrowserWindow` по образцу `window:open-sticker`, маршрут `#/capture`:

```
frame: false          рамки Windows не нужны
alwaysOnTop: true     иначе пульт утонет под бланком
skipTaskbar: true     не сорит в панели задач
focusable: false      КРИТИЧНО, см. ниже
resizable: false
transparent: true     скруглённые углы и тень
~300 × 132, правый нижний угол рабочей области (не экрана — панель задач учитываем)
```

`focusable: false` — не косметика. Если пульт при нажатии забирает фокус,
исходное окно фокус теряет, и синтетический Ctrl+C (путь Б) уйдёт в пульт, а не
в бланк. Заодно не сбрасывается выделение в приложениях, которые снимают его при
потере фокуса.

Главное окно на время захвата **скрывается** (`hide()`, не `minimize()`) — иначе
в панели задач висит бесполезная кнопка. А раз оно скрыто, нужен **значок в трее**,
которого сейчас в проекте нет: без него скрытая программа теряется. Плюс
`globalShortcut`: захват и сворачивание с клавиатуры, потому что дотянуться до
мыши иногда значит потерять выделение. Трей и горячие клавиши — новая
инфраструктура, её надо посчитать в объёме.

**Мультимонитор.** Пульт запоминает свою позицию и монитор
(`screen.getDisplayNearestPoint`); при отключении монитора возвращается на
основной. Перетаскивается за корпус, липнет к углам.

## 3. Свёрнутый пульт: состав и состояния

```
┌───────────────────────────────────────────┐
│ Выделите текст для добавления в программу │  ← строка подсказки, меняется по состоянию
├───────────────────────────────────────────┤
│  [ ✂ Текст ]  [ ⛶ Область ]      Флакси  │  ← инструменты + место персонажа
├───────────────────────────────────────────┤
│  захвачено: 10 строк, 214 знаков          │  ← что в руках
│                        [ ✓ ]   [ ✕ ]      │  ← подтвердить / выйти из захвата
└───────────────────────────────────────────┘
```

Состояния и что написано в подсказке:

| Состояние | Подсказка | Галочка |
|---|---|---|
| Жду | «Выделите текст для добавления в программу» | серая |
| Буфер не менялся | «Выделение не изменилось — выделите текст и скопируйте» | серая |
| Захвачено | «Захвачено: 10 строк. Похоже на теги» | активная, зелёная |
| Похоже на таблицу | «Захвачена таблица 12 × 4» | активная |
| Не текст | «В буфере картинка — распознать?» | активная, ведёт в OCR |
| Слишком много | «Захвачено 180 000 знаков — обрежу до 50 000» | активная с предупреждением |
| Копилка | «В корзине 3 захвата» | активная, «разобрать всё» |

Панель инструментов сделана списком с расчётом на пополнение: сейчас в ней
живой только «Текст», «Область» приходит второй фазой, дальше место под «Файл под
курсором» и «Скриншот в чат».

### 3.1. Инструмент «Область» (вторая фаза, но место под него сейчас)

Нажали — экран накрывается затемнением, курсор превращается в крест, тянем
рамку. Кадр берётся `desktopCapturer` с `thumbnailSize` **в реальный размер
дисплея** (сейчас в `desktop:capture` захардкожено 1280 × 720 — для OCR этого
мало, цифры не читаются). Дальше кадр уходит в существующий офлайн-OCR
`src/import/ocr.ts` с пулом воркеров, и результат — с **уверенностью по словам**,
которую пул уже возвращает. Слова ниже порога подсвечиваются жёлтым в области
разбора: инженер правит их до записи, а не ищет потом в карточке.

### 3.2. Корзина захватов

Данные одного бланка часто лежат в двух окнах. Поэтому галочка не обязана
открывать программу сразу: «добавить в корзину» накапливает захваты, пульт
показывает счётчик, и разбор открывается один раз на всё. В окне разбора каждый
захват — отдельная вкладка со своим источником («Excel, лист „у1“», «PDF, стр. 4»).

## 4. Окно разбора: две области

Программа разворачивается, поверх встаёт окно разбора. Слева — исходный текст
ровно как захвачен. Справа — то, во что программа его разложила.

```
┌── Захват ────────────────────┬── Разобрано: теги (10) ──────────────┐
│ AHU-2 AHU-3 P-101A P-101B    │ ✓ AHU-2                      новый   │
│ P-101C FAN-07 FAN-08 V-12    │ ✓ AHU-3                      новый   │
│ V-13 CP-1                    │ ✓ P-101A                 ⚠ есть      │
│                              │ ✓ P-101B                     новый   │
│  ← подсветка фрагмента       │ ✓ P-101C                     новый   │
│    выбранной строки          │ ✓ FAN-07                     новый   │
│                              │ … ещё 4                              │
├──────────────────────────────┴──────────────────────────────────────┤
│ Это: (•) Теги   ( ) Данные оборудования        уверенность 94%      │
│ [Отброшено: 0]  [Дубли внутри захвата: 0]              [ Далее → ]  │
└─────────────────────────────────────────────────────────────────────┘
```

Что здесь принципиально:

1. **Две области связаны подсветкой в обе стороны.** За каждой разобранной
   строкой хранится диапазон символов в исходнике (`span: [начало, конец]`).
   Встал на строку справа — слева загорелся её фрагмент. Выделил фрагмент слева —
   справа подсветилась строка. Без этого инженер не может проверить разбивку,
   а значит не поверит ей. Это тот же принцип доверия, что в предпросмотре
   импорта: видно, ЧТО именно распознано.
2. **Исходник правится, разбор пересчитывается.** Левая область — редактируемая.
   Убрал лишний перенос — разбивка обновилась.
3. **Разбор правится точечно**, не только через исходник: склеить две строки в
   одну, разбить одну на две по курсору, удалить, дописать вручную, исправить код
   на месте.
4. **Тип угадан, но переключаем.** «Это: Теги / Данные» — догадка с процентом:
   всё похоже на коды тегов из этого проекта → «Теги»; преобладают пары
   «текст + число + единица» → «Данные». Ошиблись — переключили, ничего не
   перезахватывая. Дальше «Далее» ведёт в свою ветку.
5. **Отброшенное видно.** Пустые строки, одиночные знаки, номера страниц —
   не исчезают молча, а лежат в свёрнутой секции «Отброшено (3)» и возвращаются
   одним нажатием.
6. **Черновик.** Захват можно отложить: инженеру часто надо сходить уточнить.
   Черновики живут на клиенте (`localStorage`), в БД их тащить незачем.

## 5. Ветка «Добавить теги»

### 5.1. Как режется сплошной текст

Случай из задачи: выделили десять тегов «как попало», они правильные, но идут
друг за другом. Разбивка по порядку сигналов:

1. **Перенос строки** — самый надёжный разделитель;
2. **табуляция**, затем `;`, затем `,`;
3. **пробелы** — только если ни один из предыдущих не дал разумного результата.

Пробел опасен: код `У-1 приток` разорвётся пополам. Поэтому вместо угадывания —
**шаблон кода, снятый с самого проекта**:

- берём `identifier` всех существующих тегов проекта (плюс `TagTemplate`, если
  он заполнен) и выводим их форму: какие префиксы бывают, какие разделители,
  сколько групп цифр, бывает ли буквенный хвост (`P-101A`);
- полученный образец ищем в сплошном тексте как **находки**, а не режем текст
  на куски. Что под образец не подошло — не выбрасывается, а помечается
  «сомнительный» с снятой галочкой;
- в пустом проекте, где сравнивать не с чем, работает общий образец
  (буквы-разделитель-цифры) и порог уверенности ниже — предупреждение об этом
  честно висит в окне.

Это ровно тот же приём, что «профили бланков» в разборе импорта: программа
подстраивается под то, как принято в отделе, а не навязывает свой формат.

### 5.2. Если захвачена таблица

Пришёл HTML или TSV — режим меняется на табличный, и работает уже написанное:
`detectField` из `TagImportWizard` угадывает колонки по шапке (код тега, марка,
наименование, отдел, среда, WBS, родитель, актуальность), инженер поправляет
сопоставление. Никакой новой логики, только новый источник для неё.

### 5.3. План, а не запись

Перед записью строится план (по образцу `planEquipmentImport`):

```
план = { создать: [...], дополнить: [{ тег, поля }], пропустить: [...],
         конфликты: [{ класс, код, кандидат, решение }],
         свернуть дубли захвата: [...], сомнительные: [...] }
```

Кнопка «Применить» одна, транзакция одна, отчёт один.

## 6. Конфликты тегов

Это просили продумать отдельно, и «оставить дубль или пропустить» — только два
случая из девяти. Полный набор:

| Класс | Как узнаём | По умолчанию | Ещё варианты |
|---|---|---|---|
| **Точный дубль, ничего нового** | код совпал, поля равны или в захвате пусты | **пропустить** | создать дубль |
| **Точный дубль, есть новое** | у существующего поле пусто, в захвате заполнено | **дополнить только пустые** | пропустить · заменить · дубль |
| **Точный дубль, поля расходятся** | оба заполнены и различны | **спросить**, показав дифф по полям | оставить моё · взять из захвата · поштучно |
| **Похож: регистр и дефисы** | `normalizeKey` совпал, строки разные (`AHU-2` / `ahu 2` / `AHU2`) | **привязать к существующему** + предложить починить код | создать как новый |
| **Похож: раскладка** | латиница и кириллица перемешаны (`АHU-2` с русской «А») | **привязать** + пометить «в коде русская буква» | создать как новый |
| **Похож по написанию** | Левенштейн по нормализованному ≥ 0.85 | **спросить: «это AHU-2?»** | новый тег |
| **Дубль внутри захвата** | код встретился в выделении дважды | **свернуть в один**, сказать сколько | оставить оба |
| **Тег занят другим оборудованием** | `equipmentId` указывает не на цель | **спросить**, показав, где он сейчас висит | перевесить · оставить связь · дубль |
| **Не похож на теги проекта** | не подошёл под образец §5.1 | **галочка снята**, помечен «сомнительный» | всё равно создать · исправить |

Отдельно про раскладку: `АHU-2` с русской «А» и `AHU-2` с латинской выглядят
**одинаково**, а это два разных тега в базе. Такой дубль потом не найти глазами
никогда. Поэтому это не мелочь, а отдельный класс с обязательной пометкой.

Механика решений:

- у каждой строки свой выбор, плюс «применить ко всем такого же класса»;
- решения **запоминаются на проект** (`AppSetting`): второй похожий захват
  проходит без вопросов — тот же приём, что «решения сопоставления запоминаются»
  в разборе импорта;
- дубли программа уже умеет показывать: `duplicateCodes` в `Registry.tsx`
  подсвечивает совпадающие коды и **сама гасит подсветку**, когда код стал
  уникальным. То есть «создать дубль» — не тупик: инженер увидит его и разведёт.
  Поэтому этот вариант допустим, но никогда не по умолчанию.

## 7. Подсветка добавленного

Просили: открывается дерево тегов, добавленные сразу выделены другим цветом на
несколько секунд. Разбираем по частям, потому что тут два неочевидных места.

**Что уже есть.** В `Registry.tsx` — `centerOnTag` с классом `share-pulse` на
3 секунды и `fitToTags`, вписывающий группу карточек в экран. Пульсация и
наведение камеры не пишутся с нуля.

**Как ведём себя после записи.**

1. Переходим в Реестр, в тот вид, где инженер был последним; если он там не был —
   в дерево.
2. `fitToTags(добавленные)` — вписываем все добавленные в экран.
3. Пульс по каждому, **волной с задержкой ~60 мс** (вся волна укладывается в
   1,2 с) — так читается «вот эти появились», а не «экран мигнул».
4. Держим 3 секунды, гасим за 400 мс.

**Цвета — три состояния одновременно**, потому что один захват даёт все три:

| Что | Цвет |
|---|---|
| создано | изумрудный пульс |
| дополнено | янтарный пульс |
| дубль | розовая подсветка дублей, которая в Реестре уже живёт |

**Первое неочевидное: одной вспышки мало.** Инженер отвернулся — и всё, что
добавилось, потерялось навсегда. Поэтому кроме вспышки в шапке раздела остаётся
**закрываемая плашка «последний захват: 10 тегов»** — фильтр, который показывает
только их. Живёт до следующего захвата или до закрытия вручную. Вспышка — для
глаз, плашка — для дела.

**Второе неочевидное: вспышка должна переезжать за инженером.** Подсветка
сделана под холст (`tag-card-${id}`), а просили дерево — там свои строки и свои
идентификаторы. Значит подсветку надо реализовать в каждом виде (холст, дерево,
таблица) и **перезажигать при переключении вида**, пока не истекло окно
подсветки. Иначе инженер переключится в дерево уже после вспышки и не увидит
ничего.

**Край, который сломает наивную реализацию:** если добавленные теги разбросаны по
холсту далеко друг от друга, `fitToTags` отдалит камеру так, что карточек не
разглядеть. Поэтому: если вписывание требует масштаба меньше ~0.3, не вписываем,
а показываем список «добавлено 10» и пульсируем по одному с переходом по нажатию.

## 8. Ветка «Добавить данные оборудования»

Сценарий из задачи: открыли бланк на рабочем столе, выделили текст подряд,
выбрали «добавить данные».

### 8.1. Куда кладём — выбор цели

Окно выбора, три пути вместо двух:

1. **Определить автоматически** (первым, потому что это обычный случай). Если в
   захвате нашлись коды `у1` / `мн1` / `бл2.1` или тег — предлагаем найденную
   цель с процентом уверенности и переходом к ней. Сопоставление берём готовое:
   нормализация кода (`у1 == У1 == y1 == У-1`) и fuzzy-кандидаты по названию из
   разбора импорта.
2. **В существующее** — дерево `EquipmentSystem → Monoblock → ComponentElement`
   с поиском. Дерево уже есть в `Equipment.tsx`, берём его.
3. **Создать новое** — и здесь важно, что уровней три, а не один: новая система;
   новый моноблок в существующей системе; новый элемент в существующем моноблоке.
   Плюс `equipType` (КЛАПАН / ФИЛЬТР / НАГРЕВАТЕЛЬ / …) — угадывается по
   содержимому, правится вручную.

### 8.2. Как сплошной текст становится параметрами

Из Excel пришла таблица — работает классификатор колонок из `recognize.ts`.
Из PDF-вьюера приходят строки, и нужен разбор строки на ключ / значение / единицу:

- единица ищется **в конце строки** по словарю единиц (`dictionary.ts`,
  `canonicalUnit` в `normalize.ts`);
- число — `parseRuNumber`, уже умеет «1 250,50»; диапазоны «100…120» —
  `valueGrammar.ts`;
- ключ — то, что осталось слева, с прогонкой через `normalizeKey` и алиасы
  параметров Конструктора: «Производительность» из бланка Везы сразу ложится
  ключом «Расход воздуха»;
- строка без числа и с двоеточием на конце или в верхнем регистре — **заголовок
  группы**;
- строка без числа и без двоеточия — в «Отброшено», не в параметры.

### 8.3. Дифф и конфликты данных

Дальше — существующий `planEquipmentImport` и `EquipmentImportPreview`, ничего
нового. Классы конфликтов:

| Класс | Поведение |
|---|---|
| параметр новый | добавить, отметить зелёным |
| значение изменилось | синим, со старым значением рядом |
| **изменится ручная правка** (`overrides`) | красным, спросить: моё / из захвата — поштучно и массово |
| единица не из словаря | жёлтым, спросить; **молча не пересчитываем** |
| значение вне диапазона | жёлтым — `RangeRule` в `equipmentPlan.ts` уже проверяет |
| низкая уверенность OCR | жёлтым, правка на месте до записи |
| элемент обновлён другим импортом позже | предупредить о ревизии |
| в захвате несколько блоков | не «в один элемент», а разложить деревом и выбрать область |

Про единицы отдельно: тихая конверсия кПа → Па в инженерных данных недопустима.
Только подсказка «привести 1,2 кПа → 1200 Па?» — это уже решено в разборе
импорта, и захват это решение наследует.

### 8.4. Заодно — связь тегов

Если в захвате рядом с параметрами распознан тег (ключ «Тег / KKS /
Обозначение»), план содержит связь элемент ↔ тег и опцию «создать недостающие
теги». Это закрывает самый нудный ручной шаг: обычно инженер отдельно заносит
данные, отдельно вешает теги.

## 9. Вариации взаимодействия

Собрано то, обо что живой сценарий спотыкается.

**На захвате**

- Пульт закрывает то, что выделяют → перетаскивается, липнет к углам, помнит место.
- Захват без активного проекта → сначала спросить проект: теги живут в проекте.
- В буфере картинка → сразу предложить OCR, не пытаться читать как текст.
- Захвачено 180 000 знаков → честно обрезать с предупреждением, не вешать окно.
- Тот же фрагмент захвачен второй раз → «это уже в корзине».
- Выделение внутри самой программы → работает так же; но если это карточка тега,
  предложить внутренний путь вместо разбора текста.
- Esc — выход из режима, буфер инженера восстанавливается, если мы его затирали.
- Программа развернулась, а инженер понял, что захватил не то → «вернуться к
  захвату» возвращает пульт, не теряя корзину.

**На разборе**

- Разбивка неверна → склеить, разбить, удалить, дописать, поправить исходник.
- «Это не теги, а данные» → переключатель типа, без перезахвата.
- Часть строк не нужна → галочки, применяется только отмеченное.
- В одном захвате и теги, и параметры → «разделить захват на две части».
- Отложить → черновик на клиенте.

**После записи**

- **Откат целиком.** Захват — это `ImportRun` (модель уже спроектирована в
  разборе импорта) с источником «Захват с экрана», и кнопка «откатить» на отчёте
  работает та же.
- Отчёт: создано / дополнено / пропущено / свёрнуто, с переходами к каждому.
- «Повторить с теми же решениями» — для следующего однотипного захвата.

## 10. Модель данных (дельта)

Новых таблиц почти не нужно — вот в чём выгода от того, что захват встал
источником в готовый конвейер.

- `ImportRun` — **уже спроектирован** (разбор импорта, §8). Захвату нужно только
  значение источника `SCREEN_CAPTURE` и поле `sourceMeta` (окно, приложение,
  время) для отчёта.
- Решения по конфликтам — в `AppSetting`, ключ на проект.
- Образец кода тега — выводится из существующих `Tag.identifier` на лету;
  сохранять его в БД нужно только если инженер поправил вручную — тогда в
  `TagTemplate`, который уже есть.
- Черновики захвата — `localStorage`, в БД не тащим.

Новая **инфраструктура** в главном процессе (её и надо считать в объёме):
трей, `globalShortcut`, окно пульта, слежение за буфером, полноразмерный
`desktop:capture`, сохранение и восстановление буфера.

## 12. Фазы

| Фаза | Содержание | Что даёт |
|---|---|---|
| 1. Пульт и захват текста | окно пульта, трей, горячая клавиша, слежение за буфером, флейворы, отпечаток против устаревшего буфера | текст с экрана попадает в программу |
| 2. Окно разбора | две области со связанной подсветкой, правки, отброшенное, догадка о типе | инженер видит и правит разбивку до записи |

| 4. Подсветка | волна пульса в трёх видах, плашка последнего захвата, край с далёкими карточками | «видно, что добавилось» |
| 5. Данные | выбор цели, разбор строк в параметры, дифф через готовый план | сценарий с бланком закрыт |
| 6. Отчёт и откат | `ImportRun` для захвата, откат, «повторить с теми же решениями» | доверие и аудит |
| 7. Инструмент «Область» | полноразмерный кадр, OCR, подсветка сомнительных слов | сканы и чужие вьюеры |
| 8. Синтетическое копирование | путь Б за настройкой | уходит лишний Ctrl+C |

Фазы 1–3 дают рабочий сценарий тегов и полезны сами по себе. Фаза 8 — последняя
не случайно: она единственная тянет нативную зависимость или PowerShell, и до
неё сценарий уже работает.

## 13. Отвергнутое (чтобы не возвращаться)

| Идея | Почему нет |
|---|---|
| Читать выделение из чужого окна напрямую | в Windows для Electron способа нет; всё остальное — обходные пути с ценой, которую надо назвать вслух (§2) |
| Писать в БД сразу после захвата, без плана | нарушает принцип конвейера; кривой разбор обнаружится постфактум по конфликтам |
| Свой парсер захвата, отдельный от импорта бланков | два пути разъедутся; захват — источник, а не второй конвейер |
| Считать, что «нет в захвате» значит «удалить» | захват — фрагмент; так одна выделенная строка снесёт установку |
| LLM для разбора захваченного текста | программа офлайн; образец кода из проекта и словари дают предсказуемость, проверяемую глазами |
| Тихая конверсия единиц | молчаливое изменение инженерных чисел недопустимо, только подсказка |
| Создавать дубль тега по умолчанию | дубль восстановим (Реестр его подсветит), но по умолчанию он копит мусор |
| Только вспышка подсветки, без плашки | отвернулся — потерял; вспышка для глаз, плашка для дела |
| Пульт с `focusable: true` | забирает фокус, ломает копирование и сбрасывает выделение в чужом окне |

## 14. Что проверяем перед сборкой

1. **Устаревший буфер.** Вошли в захват, ничего не выделили, жмём галочку —
   она серая, в программу ничего не попало.
2. **Флейворы.** Копия из Excel даёт таблицу с колонками; из Блокнота — список;
   картинка уходит в OCR.
3. **Связь областей.** Встали на строку справа — фрагмент слева подсветился, и
   наоборот. На каждой из десяти строк.
4. **Раскладка.** Захватили `АHU-2` с русской «А» при существующем латинском
   `AHU-2` — программа поймала похожесть и пометила букву.
5. **Все девять классов конфликтов** §6 — по одному сценарию на класс.
6. **Подсветка в трёх видах.** Добавили, попали в дерево, переключились на холст
   в течение окна подсветки — пульс перезажёгся.
7. **Далёкие карточки.** Добавили теги в разные углы холста — не отдалились в
   ничто, а получили список.
8. **Захват не удаляет.** Захватили одну строку параметров в элемент с двадцатью
   параметрами — в плане ноль удалений.
9. **Ручные правки.** Захват задевает `overrides` — красный конфликт, а не тихая
   перезапись.
10. **Откат.** Откатили захват — состояние проекта совпало с тем, что было до.
11. **Мультимонитор.** Пульт на втором мониторе, бланк на первом; отключили
    второй — пульт вернулся.
12. **Фокус.** Нажатие на пульт не сняло выделение в бланке.
